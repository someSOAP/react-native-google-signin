# Agent development runbook

Read [AGENTS.md](../AGENTS.md) first. This guide describes the repeatable workflow;
[architecture.md](architecture.md) explains ownership and SDK boundaries, and
[verification.md](verification.md) records previous results and their limits.

## Prepare the workspace

Inspect existing changes before editing. Work in the library root and preserve
user-provided Google files, ignored local configuration, and unrelated changes.
Use Yarn workspaces with the checked-in Yarn release and the Node version in
`.nvmrc`. Android builds need the Android SDK and JDK 17; iOS builds need Xcode,
CocoaPods, and an available simulator. Consult CI for the configured toolchain.

```sh
git status --short
yarn install --immutable
node scripts/configure-example.mjs
```

The configuration script creates `example/src/config.local.json` from the
placeholder template only if it is absent. It does not configure Google OAuth.
For real testing, use the user's supplied development registrations and follow
[example setup](../example/README.md). Keep local IDs in the ignored JSON and
`example/ios/GoogleSignIn.local.xcconfig`; do not overwrite existing values or
copy credentials into tracked files. Placeholder IDs allow builds and simulated
tests, but do not establish successful OAuth.

## Choose checks by changed layer

| Change | Relevant checks |
| --- | --- |
| Documentation only | Resolve local links, verify referenced paths/scripts, run `git diff --check` |
| JS wrapper or TypeScript types | Lint, typecheck, JS contract tests, package build |
| Android coordinator/provider/bridge | Android native regression tests and example native build; device check for UI/SDK integration changes |
| iOS coordinator/provider/bridge | Coordinator XCTest and example native build; device check for presentation/callback/SDK integration changes |
| TurboModule spec or SDK/tooling versions | JS/type/package checks, codegen through both native builds, relevant native suites, isolated RN compatibility builds |
| Example UI | JS/type checks, applicable native build, deterministic UI E2E; real OAuth separately when its integration changes |

Add regression tests for changed behavior rather than rerunning unrelated device
flows to produce a larger checklist. Do not invent coverage thresholds or treat
an old green result as validation of a new change.

### JS and package

From the repository root:

```sh
yarn lint
yarn typecheck
yarn test --runInBand --coverage
yarn prepare
yarn pack --out /tmp/google-signin-review.tgz
git diff --check
```

Inspect the archive when package contents change. It should include native source
and declarations and exclude native test trees, build output, and local Google
configuration. `lib/` is generated by `yarn prepare`; edit `src/` instead.
The JS suite tests the actual wrapper with the native bridge boundary replaced.

### Android

```sh
# Root: Robolectric/JUnit tests of the production manager with a fake SDK boundary.
yarn test:android

# Native build also regenerates/autolinks the TurboModule contract.
cd example/android
./gradlew :app:assembleDebug -PreactNativeArchitectures=arm64-v8a
# Optional diagnostic coverage:
./gradlew :somesoap_react-native-google-signin:jacocoDebugReport
```

Reports are in `android/build/reports/tests` and
`android/build/reports/jacoco`. The example's default application ID is
`somesoap.reactnativegooglesignin.example`. Real OAuth requires registration of
the actual package and signing SHA-1. A copied `google-services.json` does not
register a different package, and this library does not need the Google Services
Gradle plugin. The optional `googleSigninApplicationId` override is documented
in the example guide; use it only for an unused registered test identity after
checking the selected device for an existing installation.

### iOS

Choose an available simulator and substitute its UDID:

```sh
# Root: standalone coordinator XCTest; no Google login or CocoaPods needed.
IOS_TEST_DESTINATION='platform=iOS Simulator,id=YOUR_UDID' yarn test:ios

cd example/ios
pod install
xcodebuild -workspace ReactNativeGoogleSigninExample.xcworkspace \
  -scheme ReactNativeGoogleSigninExample -configuration Debug \
  -destination 'platform=iOS Simulator,id=YOUR_UDID' \
  -derivedDataPath build CODE_SIGNING_ALLOWED=NO build
```

The standalone test project is committed under `tests/ios/AuthTests.xcodeproj`;
`scripts/create-ios-test-project.rb` regenerates it using the `xcodeproj` gem only
when necessary. XCTest results are under `tests/ios/build/Logs/Test`. Changes to
the real SDK adapter/presenter need the example build too. Open the CocoaPods
workspace rather than the example `.xcodeproj` for integration work.

### Deterministic UI E2E and real OAuth

Start `yarn example start --port 8081` from the root. In another terminal:

```sh
ANDROID_SERIAL=YOUR_DEVICE_ID yarn e2e:android
IOS_TEST_DESTINATION='platform=iOS Simulator,id=YOUR_UDID' yarn e2e:ios
```

These tests inject simulated app actions into the actual example UI. Android
selects the separate entry point through `-PgoogleSigninE2E=true`; iOS uses the
debug launch argument `--google-signin-e2e`. They prove app-controlled status,
failure, retry, and logout behavior, not native Google authentication. Restore
the normal Android build after E2E; launch iOS normally without the debug argument.

For native auth UI checks, use Mobile Dev when available, select the user's device,
and confirm the normal source-linked app is running. For cross-platform work,
check Android before iOS. Use development accounts already authorized for the
task; the user enters any missing login credentials in Google's UI. Never print
or inspect token values to demonstrate success. Verify safe credential status,
cancellation without fallback, explicit retry, cleanup, and subsequent selection.
Do not remove accounts or reset data to manufacture a no-account/reauth scenario.
Record those scenarios as unverified when a disposable device/account is absent.

### RN 0.86.3 compatibility

Keep the main workspace at its baseline RN version. Use a new isolated directory
and a Node version supported by RN 0.86.3 (the recorded run used Node 24.16.0):

```sh
node scripts/prepare-rn-compat.mjs /tmp/google-signin-compat 0.86.3
```

The script excludes local Google configuration and generated/dependency trees,
pins React/RN tooling, and selects RN's separate Jest preset. Follow the install,
test, and native build commands in [example/README.md](../example/README.md#rn-0863).
After changing source again, use a fresh copy; do not claim the earlier snapshot
contains the final edits. Rerun CocoaPods integration if the Xcode project is
refreshed: RN's prebuilt Swift module paths are generated by Pod install.

## Troubleshooting and reporting

- Confirm Metro's workspace and port before starting another server. The example
  must resolve this repository's source; a registry build can hide your changes.
- Native spec changes need a rebuild. Do not manually repair generated bindings.
- Watchman is disabled in the Jest configuration for restricted environments.
- An Android provider cancellation after account selection may indicate OAuth
  registration mismatch. Check package/certificate configuration and preserve
  cancellation behavior; do not add a retry loop to conceal setup failures.
- iOS URL-scheme validation cannot prove delegate forwarding. Successful login
  and callback need a real OAuth round trip; opening Google's page is insufficient.
- Record SDK-cache/network/toolchain blocks explicitly and continue independent
  checks. Do not erase broad caches or user device state as a routine fix.

Update the verification matrix when behavior or evidence changes. Include dates,
platform/device and RN version, commands actually run, and passed/failed/not
verified outcomes. Keep native fakes, simulated UI E2E, build compatibility,
runtime launch, and real OAuth distinct. Explain exact missing inputs and avoid
claiming a remote CI result from local execution. Do not publish or push unless
the user explicitly requests it.
